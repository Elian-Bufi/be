Una operación protegida: activar un plan

1 · El website pide activar, con una clave de idempotencia

2 · La API abre una transacción y bloquea esa clave

3 · El PDP decide con el vínculo y el consentimiento, y lo registra

4 · Se escriben la versión activada, el proceso y la novedad

5 · Se audita, se guarda la respuesta y se confirma

6 · Después, fuera de la transacción: el aviso push

Por qué importa

Si algo falla, no cambia nada

Un reintento recibe la misma respuesta

Una revocación previa se respeta

El aviso no frena la operación

Así es una escritura protegida, con nombres reales de clases en la lámina E-01 del anexo E. El website pide activar un plan con una clave de idempotencia. La API abre una sola transacción y bloquea esa clave. Dentro de la transacción, el punto de autorización decide con el vínculo y el consentimiento del momento, y registra su decisión. Recién ahí se escribe: la versión activada, el proceso y la novedad para el asesorado. Se audita, se guarda la respuesta y se confirma todo junto. El aviso push sale después, fuera de la transacción. Resultado: si algo falla no cambia nada, un reintento no duplica y una revocación que llegó antes se respeta.
