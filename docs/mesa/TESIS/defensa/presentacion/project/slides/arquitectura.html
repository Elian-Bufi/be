Por dentro son cinco piezas: la APK, el website, la API, la base de datos y una tarea programada que pide los recordatorios tres veces por día. Las aplicaciones nunca hablan con la base: todo pasa por la API. La API es un monolito modular, un solo proceso con veintidós módulos por dominio, y eso es una decisión: una operación de salud tiene que ser completa o no ocurrir, y con una sola base alcanza una transacción local. Todo corre en Render, en Frankfurt, pero con Docker y PostgreSQL estándar; hasta las fotos van en la base. Láminas ARQ-02 y ARQ-03 en el apartado 8; la decisión es el ADR-01 del anexo H.
