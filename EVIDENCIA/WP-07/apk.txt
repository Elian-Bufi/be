Nota de procedimiento: el primer intento de este build salió con el commit vacío, porque se lanzó con
archivos sin commitear en el árbol de trabajo. Un APK sin su commit no cumple la identidad que exigen
07 §34 y TEST-APK-008, así que se descartó y se rehizo con el árbol limpio. Este es el segundo.

Búsqueda de secretos (cantidad de coincidencias, se espera 0 en todas). Se revisan los dos archivos del APK que
llevan código o configuración: el bundle (bytecode de Hermes, cuyas cadenas quedan legibles) y assets/app.config.
Las contraseñas y los correos de las cuentas demo se leen de .env.cuentas-demo y solo se cuentan, nunca se imprimen.
                      bundle   app.config
  JWT_SECRET          0        0
  secreto local       0        0
  token bearer        0        0
  contraseña demo     0        0
  correo demo         0        0

Las pantallas de WP-07 están en el bundle desplegado. Se buscan solo cadenas **ASCII puras** del copy:
el bundle es bytecode de Hermes, y su tabla de cadenas guarda en UTF-16 todo lo que lleva tilde o eñe, así que un
texto como «Podés no responder» no se encuentra con una búsqueda de bytes aunque esté. Un 0 en una frase acentuada
no probaría ausencia; por eso no se usa ninguna.
  «Declarado por la persona»   1
  «Corregir mi respuesta»      1
  «Sin responder»              1
  «Respondida»                 1
  «Enviar respuesta»           1
  «Completar»                  1

La misma limitación vale para el control de secretos de arriba, y no lo debilita: las cadenas que se buscan
—JWT_SECRET, el secreto local, «Bearer ey», la contraseña y el correo de la cuenta demo— son todas ASCII.
